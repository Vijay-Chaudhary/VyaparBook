# UI Backlog

Lightweight tracking for frontend work — bugs, features, and UI polish across the
Blade shell and the React islands under `/app/*`. This doc is the fast, in-repo
capture point; anything that needs assignment, discussion, or a milestone should
graduate to a **GitHub issue** on `Vijay-Chaudhary/VyaparBook` under the matching
label (`bug`, `feature`, `ui`).

## Conventions

- **ID** — `B-01` (bug), `F-01` (feature), `U-01` (ui polish). Never reuse an ID.
- **Status** — `todo` · `in-progress` · `blocked` · `done`. Keep `done` rows for one
  release, then prune.
- **Area** — where it lives, e.g. `khata`, `stock`, `onboarding`, `billing`,
  `platform-console`, `offline/sync`, `shell`.
- **Issue** — link the GitHub issue number once one is opened (`#12`), else `—`.
- Newest items go at the top of each table. One line per item; put detail
  (repro steps, screenshots, acceptance criteria) in the linked GitHub issue.

| F-20 | done | infra/tenancy | PostgreSQL → **MySQL 8**. The engine change is the small half; the isolation change is the real one. **What was given up:** 23 RLS policies covering 27 tables — MySQL has no row-level security, so the guarantee that the *database* refused a cross-tenant read is simply gone; the two-role `pgsql`/`pgsql_migrate` split with it, since that split existed only so the app role could not bypass RLS; PgBouncer, which was in the stack for transaction-pooled `SET LOCAL` GUCs that no longer exist; the lock-free global `sync_seq_global` sequence; and **19 tests** that proved engine-enforced isolation with the app layer deliberately bypassed — deleted rather than rewritten, because a green `StockRlsTest` would claim isolation is proven when it is not. **What replaced it:** `BelongsToTenant` inverted from fail-**open** to fail-**closed** — it previously added no predicate when no tenant was bound, which returned every tenant's rows and was safe *only* because RLS refused underneath; it now throws `TenantContextMissing`. Cross-tenant work goes through `Tenancy::withoutTenant()`, deliberately a named class rather than a flag so `grep -rn withoutTenant` answers "where can isolation be bypassed?" in one command — **four sanctioned sites**: the two seeders, auth before tenant selection, and the WhatsApp STOP write. The gap the scope structurally *cannot* close is raw builders (`DB::table()` walks straight past a global scope, and the report services use them throughout), so a **test-environment query tripwire** fails any test whose SELECT touches one of the 27 tables without a `business_id` predicate; it is test-only because string-matching SQL is too blunt to gate production traffic on. The platform console keeps the surviving half of the old BYPASSRLS role: `vyapar_platform_ro` is granted SELECT and nothing else, so the superadmin console **physically cannot mutate** a tenant's data however wrong the code gets. `sync_seq` became a **per-tenant counter** (`UPDATE ... LAST_INSERT_ID(value + 1)`); a single global counter row would have serialised every write on the platform against one row lock, and the invariant only ever needed monotonicity *within* a tenant because the delta pull is always scoped by `business_id`. **The money model was the thing most at risk and is intact:** 41 decimal columns and ~2,700 bcmath assertions depend on PDO returning `DECIMAL` as a *string*, which MySQL does only with native prepares — `ATTR_EMULATE_PREPARES` would silently return floats and drift khatas by paise, so `DecimalFidelityTest` now pins it. Postgres-only SQL was translated, not deleted: 46 `::text`/`::int` casts became `CAST(... AS CHAR/SIGNED)` **because** they exist to keep money in strings, plus `jsonb @>` → `JSON_CONTAINS`, `regexp_replace`'s `g` flag, and `ilike` → `like` (`utf8mb4_unicode_ci` is already case-insensitive). Also worth recording: the test harness's between-test sweep had to stop using `TRUNCATE`, which is DDL in MySQL and cost **6.2s per test** across 42 tables — `DELETE` plus a targeted `AUTO_INCREMENT` reset costs 11ms. See spec `docs/superpowers/specs/2026-07-30-postgres-to-mysql-design.md` and plan `docs/superpowers/plans/2026-07-30-postgres-to-mysql.md`. | — |
| F-19 | done | stock/production | Owner corrections, part 2 — stock and production, completing Phase 3. **A sizing claim of mine was wrong and worth recording:** I said this needed new offline outbox mutation types. It did not. Stock and production writes are **online-only, straight to the REST API** — `SyncController::push` has never accepted a stock or production mutation — so there was no offline conflict story to design. New `reverses_id` on `stock_movements` and `production_batches`: nullable, self-referencing, **no cascade**, because a correction must not vanish with its original or the sums it balances go wrong. New `App\Stock\StockReverser`, kept **separate** from `LedgerReverser` — that one is about the khata, where a correction changes what a customer owes; nothing here touches money owed and the two share only a shape. **Movement reversal flips `kind`** (in↔out, adjust→adjust) rather than copying it: the schema's invariant is that an `out` can never raise stock, so a copied kind on a negated qty would store a row contradicting its own sign. **Batch reversal undoes both halves** — negated `output_kg`, negated `material_consumptions`, and reversing movements putting the raw materials back — because the batch did both; negating only the output would leave materials consumed by a batch that no longer counts, and would skew the COGS ₹/kg (Σ cost ÷ Σ output) by moving only the denominator. **Refuses to reverse a movement that a batch or purchase created**: those are not free-standing facts, and reversing one alone would leave its cause disagreeing with stock. Corrections are dated **today**, like a voided sale, so no past month's production chart is rewritten. Orders streamed only to the salesman who took them, so nobody else's phone had heard of an order and nobody else could mark it delivered; since **delivery creates the sale**, the money never landed either. **The server already allowed this**: `roleAllows()` gates writes by role, and `deliver`/`pack`/`cancel` carry no creator check anywhere — withholding the row was the only thing in the way, so this widens visibility and no authority. It also removes an inconsistency rather than creating an exposure: `sales`, `sale_lines`, `customers` and `payments` already stream **wholesale** to every user in the tenant, so a salesman could already read every sale (the money) while being denied the order (the working state that precedes it).
